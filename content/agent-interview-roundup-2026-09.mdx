一条来自面试官。他在复盘里写：「上午面了六个 Agent 应用开发岗，简历清一色写得很满：LangGraph、CrewAI、MCP、RAG、记忆系统，关键词基本全覆盖。但问到落地细节，大部分撑不过三轮追问。」

## 面试官到底在追问什么

那位面试官的复盘给出了完整的追问路径，值得单独拆开看，因为它解释了「关键词全覆盖却撑不过三轮」是怎么发生的。

**第一层**是工具调用稳定性：模型调工具报错、参数不符合 schema、下游服务超时，代码层面怎么做异常处理？他记下的结果是「多数回答停留在 try-except 捕获一下，明显只跑通过正常路径」。

**第二层**往逻辑链条上追：模型是直接调 API，还是先走记忆检索？工具返回结果做不做格式校验？他的观察是「到这一步，很多人的回答已经开始缺乏逻辑链条」。

**第三层**直指记忆系统。场景是用户对话到第二十轮，Agent 丢失了最早的关键信息，排查路径是什么？他给了三种病因：没做记忆分层、长期记忆召回策略有问题、上下文窗口被塞爆。答不出这三样，说明「只是在调接口层面打转」。

三轮下来，筛掉的不是不知道 ReAct 的人，是没在真实业务里处理过失败路径的人。他给的准备方法是把项目按四个维度重拆一遍：

| 维度 | 要能答出的问题 |
|------|--------------|
| 数据层 | 知识库怎么清洗、按什么策略切分？ |
| 工具层 | 失败重试策略是什么，超时怎么降级？ |
| 记忆层 | 多轮上下文怎么管理，关键信息怎么召回？ |
| 工程层 | Token 成本怎么控制，异常怎么收敛？ |

一套完整的方案他还要求覆盖：日志重放机制、关键节点断言、Bad Case 闭环复盘。

## 高频题的变化：9 月 vs 7 月

把这次 11 场和站内 7 月整理的 TOP 题对比，变化集中在四处：

| 题目 | 7 月状态 | 9 月情况 |
|------|---------|---------|
| ReAct 框架 | TOP1 必考 | 仍必考，问法升级为「核心执行流程 + 三个要素各承担什么作用」 |
| Function Calling | TOP2 必考 | 仍考，更常与异常处理、Tool Message 消息结构一起问 |
| RAG 系统设计 | TOP3 高频 | 要求明显提高：父子索引、BM25 + 向量混合、Rerank 位置、索引更新与缓存失效 |
| 幻觉处理 | TOP4 | 仍在（影石第 4 题），已不是主考点 |
| 多智能体架构 | TOP5 | 演进为「单 Agent / 多 Agent / Workflow 三选一的取舍」，并追问为什么用状态机不用线性 Chain |
| 上下文窗口管理 | 第 8 题 | 升格为高频核心题：滑动窗口 vs 动态摘要、压缩丢细节怎么办 |
| MCP | 第 14 题（新知识） | 升格为刚需，同一场被连问三题 |
| Memory 机制 | 第 10 题 | 升格，与上下文压缩合并成一大类考点 |
| **Harness / Runtime / Sandbox** | 无 | 全新考点，字节 Infra 与影石均出现 |
| **Agent 评测** | 第 16 题 | 升格为独立岗位，出现 JD 拆解 |
| **AI Coding 实践** | 无 | 全新考点：Claude Code 使用习惯、AI 审核如何放行代码、被 AI 带偏怎么办 |
| **Agent 安全（Guardrails）** | 无 | 全新考点（寒武纪）：提示注入的输入 / 输出侧拦截、命令注入与 SSRF 防护 |
| **A2A 协议** | 无 | 全新考点（寒武纪）：与 MCP 的区别，为什么企业级要同时集成两套 |
| **国产算力适配** | 无 | 寒武纪专属：MLU vs CUDA 推理差异、MagicMind 动态 shape、算力仅 60% 时如何裁剪 |
| **业务场景题** | 少见 | 京东把它做成了主线：导购 Agent 设计、需求模糊处理、幻觉资损、无货排查 |
| 后端八股 | 列为「笔试基础」 | 成为面试主体（MySQL / Redis / MQ / 线程池 / JVM） |

四处变化里，**评测**和**安全**是同一类：它们从「加分项」变成了「有独立岗位」和「成体系考」。Harness 和 A2A 则属于概念层的新增——2026 年 7 月的题库里还找不到这两个词。

## 哪部分能背，哪部分只能自己踩

美团那份面经附了参考答案，是这批样本里唯一可以当模板用的。它给出的框架有四个：

- **Function Calling 三层兜底**：强约束 Prompt 限定 JSON 格式 → 代码层正则校验与字段补全 → 解析失败降级到预设固定工具流程
- **记忆一致性三原则**：统一写入与更新规则（新信息覆盖旧冗余）；关键业务数据做固定锚点不可覆盖；每次推理前优先加载核心记忆
- **向量索引选型**：数据量大、查询频次高的用 HNSW；更新频繁、实时性要求高的用 FLAT
- **缓存与库一致性**：先更新数据库再删除缓存，加定时巡检自动修复不一致数据

**代价在这**：这四条能背，是因为它们描述的是通用机制。但面试官复盘的第三层追问——「用户对话到第二十轮丢失了最早的关键信息，排查路径是什么」——背不出来，因为你得知道自己那套系统具体在哪一层丢的。

同样能背的还有边界清晰的协议题：MCP 管 Agent 怎么接工具，A2A 管 Agent 之间怎么对话。不能背的是决策题：算力只有 A100 的 60% 时优先裁剪哪些层级，线上步数爆炸时先调哪三个开关。后者只有真跑过系统的人答得出。

## 求职体感

三条来自一线候选人的判断，都指向同一件事——投递策略比知识储备更能决定结果。

**「Agent 不是一个岗位，是一类岗位」**（已入职者复盘，29 赞）。各家要的东西天差地别：偏模型应用的、偏工程落地的、偏中台架构的。没搞清楚方向，准备的东西大概率跑偏。他还提到投递渠道：别只盯大厂官网，国聘网、中智招聘上有不少国企和子公司的 Agent 岗，竞争小很多。

**「别被 JD 吓住，先上桌再说」**（23 赞）。这行最大的特点是没有统一标准，JD 上「精通 Agent 架构」大半是 HR 抄的。新手搞定三样算入门：工具调用、智能循环、MCP 协议。求职时别只搜「Agent」，顺手搜「智能体」「LLM 应用」，很多公司挂的岗位名字不一样，活儿差不多。

**「不用学那么多，多投多面才是最快的」**（682 赞）。原话是「大概学了一个月，从 6 月中到 7 月中，找实习感觉还是看运气的，多投多面才是最快的」。

把这条和面试官的观察放在一起，矛盾就解开了：面试官筛的是撑得过三轮的人，而投递密度决定的是你能不能撞上不问穿三轮的面试。两件事不冲突，是同一个策略的两半。

## 长图面经是怎么读出来的

11 场里有 3 场的正文完全在长图里（寒武纪 43 题、京东 25 题、美团 10 题）。四条路径里只有一条能走通：

| 尝试 | 结果 |
|------|------|
| `xiaohongshu download` | `Navigation rejected` |
| `xhs-media`（iPhone UA 抓 HTML） | 抓到「你访问的页面不见了」，0 张图 |
| curl 原图 URL（剥掉后缀） | 403 |
| curl 原图 URL（沿用自带后缀）+ Referer | 200 |

浏览器会话打开笔记页后，图片地址在 `window.__INITIAL_STATE__.note.noteDetailMap` 的 `imageList` 里。拿到 URL 要做两处改动才能下载：`http://` 换成 `https://`（否则被混合内容策略拦掉），以及**沿用 URL 里自带的渲染后缀**。后缀不固定——多数笔记是 `!nd_dft_wlteh_webp_3`，但至少有一篇是 `!nd_dft_wgth_webp_3`，写死会静默失败（`curl` 仍返回 0，落下一个 0 字节文件）。下载时还要带 `Referer: https://www.xiaohongshu.com/`。
