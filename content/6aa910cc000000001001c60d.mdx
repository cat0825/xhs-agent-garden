## 面试信息

- **面试岗位**：AI Agent
- **面试时长**：1h30min
- **面试体验**：★★★★

> 这份面经难得地**自带参考答案**，可以直接当答题模板对照。

## 1. ReAct、CoT、Self-reflection 三种 Agent 范式，适配美团业务分别怎么选型？

CoT 适合简单咨询、规则查询类轻量场景，用来提升推理准确度；ReAct 是美团核心选型，适合需要频繁调用工具、多步骤执行的履约、售后任务，能做到边思考边调用工具闭环；Self-reflection 适合高精度 B 端经营报表、费用核算场景，通过自我复盘修正结果，规避业务错误。整体业务优先 ReAct，简单场景用 CoT，高精度场景叠加自省机制。

## 2. Function Calling 完整执行链路，模型输出参数不规范、解析失败如何兜底？

完整链路是用户提问 → 需求解析 → 工具筛选 → 模型生成结构化参数 → 参数校验 → 工具调用 → 结果汇总。针对参数不规范问题，做三层兜底：一是通过强约束 Prompt 限定 JSON 格式；二是代码层做参数正则校验、字段补全；三是解析失败触发降级，改用预设固定工具流程兜底，保证任务不中断。

## 3. 多工具并发调用场景，如何规避工具冲突、调用混乱、重复执行？

首先做工具权限隔离，同类互斥工具禁止同时调用；其次增加任务唯一 ID 和幂等校验，拦截重复请求；最后通过工作流编排限制调用顺序，核心串行、非核心并行，从规则和代码两层规避冲突与混乱问题。

## 4. Agent 短期、长期记忆如何拆分？不同业务场景的触发机制是什么？

短期记忆存储单次会话、临时交互信息，会话结束自动失效，适配单次售后咨询、规则查询；长期记忆持久化存储用户偏好、历史订单、商家经营数据，通过向量数据库持久化，适配长期商家经营辅助、用户复购服务。

## 5. Agent 任务执行失败，如何通过 RAG 检索历史业务方案辅助纠错？

任务失败后自动触发异常检索，通过失败场景、错误类型检索历史同类问题的最优解决方案，作为 Few-shot 样本注入 Prompt，辅助模型修正工具调用逻辑和参数，实现自主纠错重试，提升任务成功率。

## 6. 多轮对话、多步骤任务中，如何保证记忆一致性，避免信息错乱、前后矛盾？

一是统一记忆写入与更新规则，新信息覆盖旧冗余信息；二是关键业务数据做固定锚点，不可被后续对话覆盖；三是每次推理前优先加载核心记忆，保证多轮输出逻辑统一，杜绝前后矛盾。

## 7. 向量数据库不同索引结构，适配美团商家知识库、配送规则库如何选型？

商家知识库数据量大、查询频次高，选用 HNSW 索引，兼顾查询速度与准确率；配送规则库数据更新频繁、实时性要求高，选用 FLAT 索引，保证更新精准、无误差，适配履约动态场景。

## 8. Agent 高并发场景下，如何用分布式锁避免任务抢占、重复调度？

针对定时批量任务、多实例调度场景，基于 Redis 分布式锁抢占任务，同一任务同一时间只允许一个实例执行；同时绑定任务唯一 ID + 过期时间，防止死锁和任务重复执行。

## 9. 内存缓存与数据库 Agent 状态不一致，如何保证最终一致性？

采用缓存更新策略，先更新数据库，再删除缓存；同时增加定时巡检机制，定时比对缓存与数据库任务状态，自动修复不一致数据，最终保证 Agent 任务状态统一、可追溯。

## 10. 模糊用户需求、残缺业务指令，Agent 如何自主拆解、补全信息、完成闭环？

通过意图识别判定残缺需求，结合业务知识库补全缺失信息；再通过任务拆解拆分多步骤子任务，依次调用对应工具执行；全程记录任务状态，异常自动重试，最终完成全流程业务闭环。
