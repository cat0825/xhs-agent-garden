## 一页速览：学什么、先学什么

| 优先级 | 学什么 | 为什么是它 | 达标标准 |

| **P0** | Agent 智能循环（Loop） | Agent 区别于 RAG / 问答的根本，面试主线 | 能画出 接任务 → 思考 → 行动 → 观察 → 再决策 的闭环，并说清终止条件 |

## P0 · 底座：不过这一关，简历再满也撑不过三轮追问

### 1. 工具调用与异常处理

这是**最容易被追问穿的一层**。有面试官直接点评过：简历上 LangGraph、CrewAI、MCP、RAG、记忆系统关键词全覆盖，但"问到落地细节，大部分撑不过三轮追问"，回答停留在"try-except 捕获一下"，明显只跑通过正常路径。

要能答出这三层：

| 层 | 具体做法 |
|----|---------|
| 参数层 | 工具返回结果做 **schema 校验**，不合法就回灌错误给模型重生成 |
| 网络层 | 超时重试用**指数退避**，并设置最大重试次数 |
| 业务层 | 异常链路**降级**到人工兜底或默认返回值，不静默失败 |

**面试原题**：

- 模型调工具报错、参数不符合 schema、下游服务超时，代码层面怎么做异常处理？
- Agent 调用工具后，工具返回结果时消息结构如何设计？为什么需要单独设计 Tool Message？（虾皮）
- 工具或 API 调用超时、报错时，系统如何处理？是否考虑过让大模型参与异常处理或自动恢复？（影石）
- 当工具越来越多，上下文信息杂乱，Agent 选工具容易出错，可以怎么优化？

关键判断：**这些不是看文档能记住的，是线上故障倒逼出来的**。自己造故障比背答案有用。

### 2. Agent 智能循环（Loop）

面试官现在的问法是"把完整运行链路串起来讲一遍"，而不是"你用过 LangChain 吗"。

字节 Agent 研发（基础设施）岗明确给出的追问链：

```
Agent Loop 怎么跑
  → Runtime 提供什么能力
    → Harness 解决什么问题
      → Memory 怎么设计
        → MCP / Skill 怎么接入
          → Sandbox 怎么提供执行环境
```

**面试原题**：

- ReAct Agent 的核心执行流程是什么？Thought、Action、Observation 分别承担什么作用？（虾皮）
- Agent 中的短期记忆和长期记忆分别如何实现？哪些信息适合长期保存？（虾皮）
- 如果从零设计一个 Agent，需要考虑哪些核心模块？（影石）
- Agent 调了三个工具后开始死循环，异常处理写在哪？（已入职者复盘）

**必答的收敛机制**：最大迭代步数、重复动作检测、熔断、Token 预算上限。

### 3. 上下文与记忆管理

"简历上写'精通记忆系统'的，一问上下文管理就暴露了。" 典型场景：用户对话到第二十轮，Agent 丢失了最早的关键信息，排查路径是什么？

要能区分三种病因：

1. 没做**记忆分层**（短期 / 长期 / 工作记忆）
2. **长期记忆召回策略**有问题
3. **上下文窗口被塞爆**，关键信息被挤掉

**面试原题**：

- 当对话超过模型上下文窗口限制时，通常有哪些处理方案？滑动窗口和动态摘要各有什么优缺点？（虾皮）
- 长上下文压缩，你了解哪些实现思路？
- 上下文为什么需要压缩？压缩后丢失细节如何处理？（影石）
- cc、codex、dsh 上下文压缩策略（ai agent 面经）
- Token 消耗过快时，如何排查和优化？（影石）

### 4. RAG 进阶链路

只会"文档切片 + 向量检索"已经不够。现在的标准链路是：

```
Query Rewriting → Hybrid Search（BM25 + 向量）→ Rerank → 上下文组装
```

**面试原题**：

- RAG 系统为什么需要设计父子索引？检索较小文本块、返回完整父文档解决了什么问题？（虾皮）
- BM25 关键词检索和向量检索通常如何结合使用？Rerank 模型应该放在哪个阶段？（虾皮）
- 知识库持续更新时，如何处理向量索引更新、缓存失效以及旧文档仍被召回的问题？（虾皮）
- 文档不拆分的 embedding 和拆分后的 embedding 结果有什么不一样？一个文档做向量化和一个文档的一个块做向量化，产生的结果维度是否一样？

### 5. 手撕 + 后端基础

后端八股并没有因为"Agent 岗"而消失，反而因为岗位常常挂在后端团队下而更硬。

**出现过的算法题**：LRU（字节 Infra）、拓扑排序 / 循环依赖检测（字节）、合并两个有序数组（影石）、三数之和（百度）、SSE 流式工具 delta 组装（ai agent 面经）、重复行检测（内存放不下时怎么做）、编辑距离、手撕 SQL 窗口函数。

**出现过的后端题**：

- **MySQL**：联合索引失效场景、LIKE 何时走索引、undo / redo / binlog 区别、两阶段提交
- **Redis**：在 Agent 系统里承担什么作用、过期策略怎么设计
- **消息队列**：解决什么问题、为什么不直接用数据库传任务状态
- **Java**：线程池核心参数与执行流程、重新设计线程池要考虑什么、class 文件如何加载进 JVM
- **并发**：线程 vs 协程 vs 进程的关系与切换成本

## P1 · 拉开差距：这些是 9 月新冒出来的考点

### 6. MCP 协议

有从业者直接把它类比为"**当年的 REST API**"——2026 年工具接入的主流标准，属于刚需。

**面试原题**（三题连续出现在同一场）：

- 讲讲 MCP？MCP 的实现方式有哪些？MCP 设计解决了什么场景？
- 介绍一下 MCP 的协议，streamable 格式？
- 要用一个 MCP，是如何与大模型结合，并且如何调用？

### 7. Harness / Runtime / Sandbox

这是 2026 年 9 月**最明显的新增概念**，中文圈和英文圈同步升温：

- X 上 ♥2495 的爆款帖把 Harness 定义为四件事：① 让模型在循环里持续工作 ② 给它读文件 / 调工具 / 跑代码的"手" ③ 管理记忆 ④ 约束它能碰什么、何时必须停下来问人
- 影石面试直接问："**如何理解 Spec Coding 和 Harness？Harness 为什么可能提升 Agent 的任务完成能力？**"
- DeepSeek 官方账号在招 Harness 团队，并已发布 DeepSeek Harness v0.1.5

**面试原题**（字节 Infra）：Harness 解决什么问题 / Runtime 提供什么能力 / Sandbox 怎么提供执行环境。

### 8. 多 Agent 编排与状态机

**面试原题**：

- 单 Agent、多 Agent 和 Workflow 编排模式各有什么优势？（虾皮）
- 为什么选状态机而不是线性 Chain？分支执行失败怎么回滚？
- 使用 deepagent、langgraph、dify 完成一个问数智能体如何设计方案，三种技术有什么区别？
- 并行边 + 多节点操作一个 state 的结果会汇总到一个节点，state 如何汇总？

真正上线过的人会讲**节点级可重试设计、分支判定逻辑、防止单点故障拖垮整条链路**。

### 9. Agent 评测

小红书已出现专门的「Agent 评测工程师｜岗位要求全拆解」（拆了 10 个 JD：阿里 / 网易 / 小红书等）。核心要求：

- **评测体系从 0 到 1** 与 **Bad Case 归因**
- 技术栈：LangChain / LangGraph / Dify / MCP，Python 是硬门槛，知道 SWE-bench 是加分项
- 评测方法：**规则校验 → LLM-as-a-Judge → 人工评审**，核心是设计 Rubric 和校准 Judge
- 评测链路工程化 8 步流程 + 质量模型五维度

**面试原题**：你们的 Agent 是怎么做效果评测的？有量化的指标吗？

### 10. Agent 安全（Guardrails）

这是寒武纪面经里成体系考的一类，其他公司也在零星问。核心三块：

- **提示注入**：输入侧和输出侧分别要拦截哪些风险
- **工具调用的攻击面**：参数校验防命令注入、SSRF 在 Agent 系统中如何暴露与防护
- **防护机制**：Guardrails 怎么做，对照 **OWASP LLM Top 10** 自查

**面试原题**：

- 讲讲真实的提示注入攻击场景，系统的 Guardrail 防护机制，在输入侧和输出侧分别需要拦截哪些风险？
- Agent 工具调用场景中，如何做好参数校验，防范命令注入攻击？SSRF 漏洞在 Agent 系统中会如何暴露，对应的防护方案是什么？

### 11. A2A 协议（与 MCP 配套）

**面试原题**：A2A 和 MCP 协议的核心区别是什么？为什么企业级 Agent 系统需要同时集成两套协议能力？

一句话记法：**MCP 管"Agent 怎么接工具"，A2A 管"Agent 之间怎么对话"**。

## P2 · 加分项与定向补强

### 12. 可观测性与成本控制

从业者建议里反复出现：LangSmith / Langfuse 这类可观测性工具，以及"**想卷赢别人，重点搞这三个：沙箱隔离、记忆管理、Token 成本优化**"——大部分人不会控成本，你懂就赢了。

寒武纪三面还把它做成了决策题："线上出现 Agent 无限循环、步数爆炸、算力过度消耗、成本飙升，你会优先调整哪三个核心开关快速止损？"

### 13. 训练侧概念（仅偏算法岗）

虾皮面经中出现："Agent 训练中的 SFT、强化学习和 Agentic CFT 分别解决什么问题？为什么需要 Mask Observation Token？" 若不投算法岗，了解即可。

## 一条可执行的 12 周路线（来自 ♥798 的「焚决」）

> 互动最高（♥798）的学习路线帖给出了明确的取舍标准：**每天 3-4 小时、周末 6 小时，总 100-120 小时，做不到就别开始。**

| 周 | 主题 | 关键任务 |
|----|------|---------|
| 1 | **打地基** | Python 异步 + Pydantic v2 + FastAPI；**手写最小 Agent Loop（50-150 行，不许用 LangChain）** |
| 2 | Function Calling | 定义工具 schema，写 5 个工具（天气/汇率/待办/日历/搜索），把超时、参数错、模型瞎编工具名全处理一遍 |
| 3 | **MCP** | 用 FastMCP 写一个文件系统 MCP Server（读/写/列目录/搜内容），部署到云函数 |
| 4 | LangGraph | StateGraph、Node、Edge、条件分支、checkpoint；做一个任务规划 Agent |
| 5 | 记忆 | 三层记忆：工作 / 会话 / 长期；长期用向量库 + 结构化存储 |
| 6 | **Agentic RAG** | 别搞固定管道，把 RAG 封成工具，让 Agent 自己决定何时检索、检索几次、结果不够怎么换 query |
| 7 | 多 Agent | Supervisor 模式搭写作团队；同时想清楚"**啥时候不该用多 Agent**" |
| 8 | 评估与可观测性 | Langfuse 追调用链、RAGAS 评检索与生成；写一份可靠性报告（正常指标/对抗测试/失败模式） |
| 9 | 部署与安全 | Docker 打包、FastAPI 接口、流式输出；Guardrails 防注入、OWASP LLM Top 10、成本分级 |
| 10 | 打磨项目 | 精选 **2-3 个**（Agentic RAG / 多 Agent 协作 / MCP Server），README 带架构图，代码有类型注解、错误处理、测试 |
| 11-12 | 面试冲刺 | 高频题 + 项目话术三层（What / How / Why）+ 至少两次模拟面试 |

**工具栈一以贯之**：Python + LangGraph + FastMCP + ChromaDB/Milvus + FastAPI + Docker。**别今天 CrewAI 明天 AutoGen，分散精力。**

**三条最硬的判断**：

1. **前 3 周不许用框架**——"你连'思考 → 行动 → 观察 → 再思考'的循环都没手写过，面试一问就露馅"
2. **Agent 和 Chatbot 的区别就一句**：Chatbot 单次问答，Agent 自主闭环
3. **没 eval 的系统就是 demo**——面试官一听就知道

> 简历怎么写？"STAR，量化。别写'使用了 LangGraph 和 MCP'，太虚。写'把工具调用准确率从 70% 提到 95%，通过优化工具描述和失败重试'。**面试官只看技术决策和结果。**"

## 学习节奏建议（按上面的路线落地）

| 阶段 | 周次 | 重点 | 产出 |
|------|------|------|------|
| **打地基** | 1-4 | P0 的工具调用、智能循环、上下文 / 记忆 | 一个能跑通 接任务 → 调工具 → 出结果 的最小 Agent，且**故意把它搞崩再修好** |
| **补链路** | 5-7 | P0 的 RAG 进阶 + P1 的 MCP | RAG 从 Query Rewriting 到 Rerank 的完整链路；接一个真实 MCP server |
| **上难度** | 8-10 | P1 的 Harness / Runtime / Sandbox、多 Agent、评测、安全 | 一个带沙箱隔离 + 评测集的项目；能讲清每层设计取舍 |
| **冲面试** | 11-12 | 手撕 + 后端八股 + 项目复盘 | 项目按「数据层 / 工具层 / 记忆层 / 工程层」四维重新拆一遍 |

**一个高效技巧**：把开源高星项目（Manus、MetaGPT 等）先跑通，然后**故意搞破坏**——让它无限迭代看怎么死、塞脏数据看怎么崩、丢超长任务看上下文怎么爆。这几个场景全是面试高频题，自己玩出来的经验比背一百道八股文管用。

## 相比 7 月版，哪些判断需要修正

| 维度 | 7 月版判断 | 9 月实际情况 |
|------|-----------|-------------|
| 框架选型 | LangChain 入门 → LangGraph 深入 → AutoGen 加分 | **LangGraph 或 OpenAI Agents SDK 二选一吃透即可**；面试官不考 API 背默，只问设计逻辑与运行机制 |
| 核心概念 | ReAct / RAG / Function Calling | 新增 **Harness / Context Engineering / Evals**，且已在真实面试中出现 |
| 后端基础 | 列为"笔试基础" | 实际是**面试主体之一**（字节 Infra 后半段基本是标准后端考察） |
| 岗位认知 | 按"应用工程 vs 算法工程"分 | 更细：**Agent 不是一个岗位，是一类岗位**（偏模型应用 / 偏工程落地 / 偏中台架构），投前必须拆 JD |
| 学习顺序 | 先学完框架再投 | **多投多面才是最快的**；有候选人学一个月就上岸，主要靠投递密度 |
