## 最大的坑：Agent 不是一个岗位，是一类岗位

我一开始猛学 LangChain，投了一圈才发现各家要的东西天差地别——有偏模型应用的，有偏工程落地的，还有偏中台架构的。**没搞清楚目标岗位的方向，准备的东西大概率跑偏**。

建议先把 JD 拆开，看它到底要的是调 Prompt 的人，还是能设计稳定系统的人。

## 2026 年的 Agent 面试，全程拷问工程化能力

我面了好几场，几乎每家都问同一个场景：**Agent 调了三个工具后开始死循环，异常处理写在哪？**

第一次被问直接懵了，因为我的 demo 压根没考虑熔断和重试。面试官想听的是：

- 最大迭代次数设了没
- 工具调用失败怎么降级
- 上下文超长怎么裁剪
- Token 成本怎么控制

大厂要的不是会写 Agent 的人，是**能控住 Agent 不失控的人**。

## 项目准备的坑

都说要有项目，但没人告诉你 **demo 和上线项目的差距有多大**。我拿 RAG demo 去面，被问到"召回不准怎么监控、怎么评测"，直接卡住。

后来才明白，面试官全程盯着项目刨根问底，你真实做过什么、踩过什么坑，一问全暴露。企业要的是**能讲清楚问题与解决方案的项目**，不是框架堆砌的流水账。

## 投递渠道

别只盯大厂官网。**国聘网、中智招聘**上有不少国企和子公司的 Agent 岗，竞争小很多。面试前把目标公司 JD 拆清楚，偏算法还是偏工程，针对性准备效率高得多。

## 技术栈

别只停留在 LangChain 线性链。现在更看重：

- **LangGraph 的状态机编排**
- **MCP 工具协议**
- **多智能体协作**
- **LangSmith / Langfuse 这类可观测性工具**

RAG 也要进阶到 **Query Rewriting、Hybrid Search、Rerank 的完整链路**，光会调向量库不够。
