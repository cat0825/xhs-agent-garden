## 正文

博主暑期找了小厂做 agent 应开 对接一个内部财务报表汇总的项目 项目完全从 0-1 交给我一个人 大概需求是 AI 解析合同以及银行回款，总和到一张汇总表，最后把汇总数据整理成数据库喂给 AI，让 AI 能基于RAG 对话
公司里的 AI 都已经封装好还有 UI 界面，点击就能解析操作，创建工作流
这工作内容跟 agent 开发有关吗？
如果秋招想冲击大厂我现在应该做些什么？
我理解实习生难道不是在做 agent 的决策/工具/记忆板块啥的吗？
各位 agent 实习生都在做些什么 ？

### 图 p08：FirstCoder 项目对比表（对应评论区推荐的 coding agent 学习项目）

> 大多数 coding-agent 演示展示的是表面：一个 prompt 进去，代码改完出来。FirstCoder 关注的是中间的机械结构。

**FirstCoder vs OpenCode 这类更大的项目**：

| 维度 | FirstCoder | OpenCode 这类更大的项目 |
| --- | --- | --- |
| 主要目标 | 把 agent 内部机制做得可读、可学、可讲清楚 | 提供更完整、更偏产品化的 coding-agent 平台 |
| 代码形态 | 核心运行时代码约 1.7 万行 Python | TS/JS 代码规模约 57 万行，平台层和工程表面更多 |
| 工程取舍 | 主动放弃一部分额外平台能力，换取更强可读性 | 接受更高复杂度，以支持更宽的产品能力面 |
| 适合谁 | 学习、二次改造、面试讲解、作品集/简历项目、本地实验 | 更想直接使用一个大而完整的 coding-agent 环境的用户 |

**FirstCoder vs 常见学习型 agent 项目**：

| 维度 | FirstCoder | 常见学习型 agent 项目 |
| --- | --- | --- |
| 学习价值 | 子系统边界清楚、文档明确，适合按模块阅读 | 往往更偏单一路径教程或 demo 流程 |
| 实用表面 | 有真实 TUI、tools、permissions、sessions、provider adapters | 往往更聚焦单个更小的 loop 或概念验证 |
| 可验证性 | 有 80+ 测试文件，并接入了多个 benchmark 入口 | 较少强调测试体系和 benchmark 集成 |
| 延展性 | 更适合继续改造成作品集或简历项目 | 更适合跟做和入门，但延展空间有限 |
